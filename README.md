# Lumen Tube

Rust + Slint, Windows / Android. **Первый этап: сетевое ядро и UI самотестирования, не готовый YouTube-клиент.**

## Workspace

| Crate | Назначение |
|---|---|
| `lumen-core` | TLS-пробы с проверкой сертификатов, автоматический выбор транспорта |
| `lumen-proxy` | Loopback HTTP CONNECT / SOCKS5, один динамический порт |
| `lumen-ui` | Общий интерфейс Slint, неблокирующая проверка сети |
| `lumen-desktop` | Windows entry point |
| `lumen-android` | Android NativeActivity, arm64, API 26+ |

## Реализовано

Кнопка запускает самотестирование без ручных сетевых параметров. По очереди проверяются:

1. Прямое соединение.
2. Разбиение первой TLS handshake record на записи по 32 байта с задержкой 5 мс.
3. Разбиение по 8 байт с задержкой 10 мс.

Принимается первый вариант, успешно выполнивший TLS + HTTP HEAD для `www.youtube.com` и `i.ytimg.com`. Используется настоящий hostname/SNI и проверка сертификата через rustls/webpki-roots. Проверка каждого endpoint ограничена 12 секундами. При полном отказе возвращается ошибка, прокси не запускается. Нет подмены сертификатов или MITM.

После успеха UI показывает выбранную стратегию и динамический loopback-порт. Один порт распознаёт SOCKS5 (только domain CONNECT/no-auth) и HTTP/1.1 CONNECT. Разрешены только YouTube-домены из списка в `lumen-core`, порт 443. Установлены ограничения заголовка, параллельных соединений и времени handshake. Обычный HTTP forwarding, UDP ASSOCIATE и аутентификация не поддерживаются. Другие процессы на устройстве могут обращаться к loopback-прокси; это не граница безопасности между локальными приложениями. Защита от злонамеренного DNS/rebinding пока не реализована.

**Важно:** несколько `write()` с TCP_NODELAY не гарантируют несколько TCP-пакетов: стек и сеть могут объединять данные. Это не IP fragmentation. В split-режиме принимается первая TLS record (до 16 KiB), не произвольный протокол.

## Чего пока нет

- Fake SNI, raw TCP sequence injection, TTL tricks и их автоматическое тестирование.
- Код ZeroDPI / sni-spoofing-rust не заимствован и совместимость с ними не заявляется. Обозначения `[reference:N]` в исходном задании не содержали URL.
- Обход настоящего IP allowlist: изменение ClientHello не делает недоступный IP доступным. Отдельный разрешённый relay/tunnel мог бы потребоваться, но не входит в эту версию.
- Проверка всех CDN/googlevideo, адаптация к смене сети, кэширование стратегий и автоматическое переключение после отказа активного транспорта.
- YouTube API, поиск, история, подписки, получение media URL и воспроизведение.
- Android VpnService, TUN forwarding, `protect()` для исключения прокси-сокетов из VPN и JNI-интеграция Media3/ExoPlayer.
- mpv/WebView на Windows. Внешние прокси-бинарники не используются; никаких плеерных бинарников также нет.
- Автозапуск проверки при открытии приложения: пока используется явная кнопка. Конфигурация параметров пользователем не требуется.

**Не обещаем обход любого DPI или «белых списков».** Успешная HEAD-проба не означает доступность видео. На Android сейчас работает только собственный loopback-сервис; системный трафик он не перехватывает. Дальнейшая интеграция плеера должна направлять его запросы через выбранный транспорт автоматически.

## Сборка и проверки — только CI

Локальные тяжёлые сборки не запускались. В рабочей среде отсутствует Rust toolchain. Workflow `.github/workflows/build.yml`:

- форматирует исходники в checkout CI, проверяет форматирование, запускает тесты и Clippy сетевых crates;
- собирает Windows MSVC release `.exe`;
- компилирует Android arm64 release библиотеку через cargo-ndk, отдельно упаковывает **debug-signed preview APK** через cargo-apk;
- сохраняет бинарники и разрешённый Cargo.lock как Actions artifacts на странице запуска.

Rust stable; Slint закреплён на 1.9.2. Cargo.lock пока не создан, поэтому транзитивные зависимости ещё не полностью зафиксированы. Следующий шаг после успешного CI — сохранить проверенный lockfile. Автоматическое форматирование CI не меняет исходники ветки.

Команды для CI/полноценной машины разработчика:

```sh
cargo fmt --all
cargo test -p lumen-core -p lumen-proxy
cargo clippy -p lumen-core -p lumen-proxy --all-targets -- -D warnings
cargo build -p lumen-desktop --release --target x86_64-pc-windows-msvc
cargo ndk -t arm64-v8a -p 26 build -p lumen-android --release
cargo apk build -p lumen-android --target aarch64-linux-android
```

Android SDK/NDK/JDK настраиваются workflow. Preview APK подписывается отладочным ключом CI; для публикации нужен отдельный безопасно хранимый release key. Бинарные результаты и runtime на реальных Windows/Android ещё не проверены. Артефакты появятся только после push и успешного workflow, ссылки до этого не существуют. Загрузка в Drive не настроена.
